Oboi Wallpaper Publisher

Privacy policy

Effective date: November 25, 2026 · Last updated: November 25, 2026

This policy describes the project website and the intended Pinterest integration of Oboi Wallpaper Publisher, an internal tool of «Обои для iPhone» (Wallpapers for iPhone). Pinterest API access is pending. The integration has not been launched for automated publishing.

1. Project operator and contact

The project and application are operated by Yaroslav, the owner of «Обои для iPhone». The project's community is vk.com/club172421211 and its Telegram channel is t.me/pacphone.

For privacy questions, access or deletion requests, contact the operator using VK community messages. Identify the request as relating to “Oboi Wallpaper Publisher”. Do not send passwords, access tokens, or other credentials in your message.

2. Scope and purpose

The application is intended only for the operator's own Pinterest account. It creates and schedules image Pins for the wallpaper project, with titles, descriptions, and links to corresponding VK posts. It is not offered for connecting accounts belonging to third parties.

This public website provides project information and this policy. Visiting the website does not authorize the application to access a Pinterest account.

3. Information used by the integration

When the owner authorizes the integration, it may process:

  • OAuth access tokens and, if issued, refresh tokens used to communicate with Pinterest.
  • The authorized account's identifier or username, and its board and Pin data, including identifiers needed for publishing.
  • Wallpaper images, titles, descriptions, and destination links selected for publication.
  • Operational records such as the last created Pin identifier, publication counts, errors, and diagnostic logs.

The current authorization configuration requests user_accounts:read, boards:read, pins:read, and pins:write. These permissions support identifying the connected account, reading its own boards and Pins, and creating Pins. The application does not request Pinterest passwords or access to private messages, advertising accounts, contacts, or payment information.

4. How information is used and shared

Information is used to authenticate the operator, publish to the configured boards, confirm publication results, and diagnose integration errors. Images, text, destination links, and authorization credentials are transmitted to Pinterest as required by its API. Publishing a Pin makes its content available according to Pinterest's settings and access-tier restrictions.

The operator does not sell Pinterest account data, use it for advertising profiles, or provide it to data brokers. Pinterest handles information under its own privacy policy. VK and Telegram handle visits and messages under their respective policies.

5. Storage and security

The integration runs in the operator's environment. Authorization credentials may be stored in local configuration files or environment variables; publication state and diagnostic logs are stored locally. Credentials are not included in this public website or its public source repository.

Access to the integration environment and its credentials must be restricted to the operator. Connections to the Pinterest API use HTTPS. No system can guarantee absolute security; this policy does not claim that local files are encrypted.

6. Retention, revocation, and deletion

Authorization credentials are retained while the owner uses the integration. Publication state and diagnostic records are retained while needed for operation and troubleshooting. The owner can stop publishing, revoke the app's access in Pinterest settings, and remove locally stored credentials and records when no longer needed.

To request access, correction, or deletion of information held by the operator, use the contact route above. The operator may need to verify that a request relates to the authorized account before acting. Revoking access or deleting local records does not itself delete Pins already stored on Pinterest; those must be managed through Pinterest.

7. Website hosting and cookies

The website is designed for hosting on GitHub Pages. It contains no application sign-in, contact form, advertising scripts, embedded social widgets, or analytics scripts. The website itself does not set cookies or use browser storage.

GitHub processes technical information associated with website requests. In particular, GitHub states that visitors' IP addresses are logged and stored for security purposes. See GitHub Pages documentation and the GitHub privacy statement. Following external links takes you to services with their own data practices.

8. Changes

This policy will be updated if the application's data practices or scope change. The effective and last-updated dates appear at the top of this page. Any future connection of third-party accounts would require an updated description and policy before that feature is offered.

Какие данные и зачем

Владелец проекта — Ярослав. Oboi Wallpaper Publisher предназначен для публикации обоев только в собственном аккаунте Pinterest. Доступ к API пока не одобрен, автоматическая публикация ещё не запущена.

После авторизации инструмент сможет работать с данными своего аккаунта, его досок и пинов, изображениями, текстами и ссылками публикаций. Токен авторизации, служебные записи и журналы хранятся в окружении владельца, а не на публичном сайте. Данные не продаются и не используются для рекламного профилирования.

Сам сайт не содержит аналитики, форм, входа или собственных cookies. Хостинг GitHub может обрабатывать технические данные посещений, включая IP-адреса для безопасности. Для вопроса об обработке или удалении данных напишите владельцу через сообщения VK-сообщества. Не присылайте пароли и токены.

Доступ приложения можно отозвать в настройках Pinterest. Удаление локальных данных не удаляет уже созданные пины — ими нужно управлять в Pinterest. Полное описание обработки приведено выше на английском языке.
